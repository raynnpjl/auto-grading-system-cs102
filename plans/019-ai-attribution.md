## Why this matters

The project brief requires the following. Short quotes from the brief:
- "Use comments to attribute specific methods", with the example `// Generated by ChatGPT-4; modified for tie-breaker logic`.
- An "AI Use" section in the slides' appendix "listing the tools and prompts used for major architectural decisions".
- "Every team member must be able to explain the logic and implementation of any AI-assisted code."

Today the attribution is a single **file-level** first line, `// Generated by Codex` (78 files) or `// Generated by Claude Code` (57 files). Ten UI files, written with Claude Code in a later session, have **no** attribution at all. File-level tags don't say what the team changed. That's the part that shows accountability, and the Q&A will probe it.

## Current state (at `e820cd4`)

- Files with no attribution: `src/main/java/ui/{ResultsTable, ScoreSheetConfirmation, AutoGradingApplication, MainViewController, StartupCheck, SimilarityList, IdentityDialog, StudentDetailPane, GradingSummaryText, FindingsText}.java`, plus any files added by plans 008–018.
- Header format in the attributed files: line 1 is `// Generated by Codex` or `// Generated by Claude Code`, followed by the `package` line.

## Steps

### Step 1: Inventory

Write `plans/ai-attribution-inventory.md`, a table with one row per Java file: path, current header (or "none"), and the tool that wrote it. For files without a header, take the tool from `git log --format='%an %s' -- <file>`, or ask in step 2. Leave the "Team changes" column blank.

### Step 2: Ask the user (don't guess)

Ask these questions, one at a time:
1. Which AI tools were used, and roughly for which packages?
2. For each package, which methods did the team **substantially modify or write themselves**, and what was changed? Offer the inventory as a checklist.
3. Which prompts drove the major architectural decisions? These go on the slide, so 3–6 is enough. For example: the `GradingSession` model, the timeout-recovery approach, the similarity algorithms (winnowing and greedy string tiling), and the JavaFX-vs-web decision.

### Step 3: Apply

- Keep a file-level header where the whole file was generated. Make it follow the brief's format, adding what the team changed: `// Generated by Codex; modified by the team for <change>`.
- Add a method-level comment directly above each method the team identified as modified: `// Generated by <tool>; modified for <reason>`.
- Add headers to the files that have none, using the user's answers.

**Verify**: `grep -rL "Generated by\|Written by the team" src/main/java src/test/java` → empty. `./mvnw -q -B -DskipTests compile` → exit 0 (comments only).

### Step 4: Slide content

Write `plans/ai-use-slide.md`, containing:
- the tools;
- the 3–6 prompts with the decision each led to;
- one line on how the output was verified: 167+ automated tests, the end-to-end ground-truth test from plan 017, and the style self-check from plan 018.

The team pastes this into the deck's appendix.
